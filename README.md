# جستجوی هوشمند دیوار — اپلیکیشن اندروید (کاملاً مستقل، بدون سرور)

Kotlin + Jetpack Compose، معماری Clean Architecture (Data / Domain / Presentation) + MVVM، Material Design 3.

## این نسخه چه فرقی با نسخه قبلی دارد؟

نسخه‌های قبلی به یک بک‌اند Python جدا (روی کامپیوتر) و یک افزونه مرورگر Chrome
نیاز داشتند. **این نسخه کاملاً مستقل است** — همه‌چیز داخل خود اپ اجرا می‌شود:

| قبل | حالا |
|---|---|
| سرور FastAPI + PostgreSQL | دیتابیس محلی روی گوشی (Room / SQLite) |
| افزونه Chrome روی کامپیوتر | یک تب مرورگر **داخل خود اپ** (WebView) |
| فیلترها/AI روی سرور (Python) | همان منطق، پورت‌شده به Kotlin، مستقیم روی گوشی |
| نوتیف از طریق Firebase (FCM) | نوتیف محلی مستقیم از خود اپ |

فقط یک اپ نصب می‌کنید — نه کامپیوتر لازم است، نه سرور، نه افزونه.

## فلوی استفاده

1. **جستجوی جدید بسازید** (فرم فیلترها → فیلترهای دائمی → ذخیره)
2. در «جستجوهای من»، روی آیکون 🧭 «باز کردن و رصد» بزنید
3. یک تب مرورگر داخل خود اپ باز می‌شود که صفحه جستجوی دیوار را نشان می‌دهد
4. همان‌طور که در دیوار می‌گردید (لیست یا صفحه یک آگهی)، اپ به‌صورت خودکار و
   passively (بدون هیچ درخواست شبکه‌ای اضافه) متن صفحه را می‌خواند، فیلتر
   می‌کند، و نتایج را ذخیره/اعلان می‌دهد
5. نتایج در تب «نتایج» و تاریخچه در تب «تاریخچه» قابل مشاهده است

## معماری

```
presentation/   Compose screens + ViewModels (MVVM)
domain/         Use cases + repository interfaces + domain models
data/
  local/        Room database, entities, DAOs, mapperها
  filters/      فیلتر شماره مسدود، کلمات ممنوعه، تشخیص مالک با AI (Kotlin)
  webview/      استخراج آگهی از WebView + سرویس ingestion
  repository/   پیاده‌سازی repositoryها روی Room
di/             ماژول‌های Hilt (Database, Repository)
notification/   نوتیفیکیشن محلی (بدون FCM/سرور)
```

## فیلترها (همه روی گوشی، بدون سرور)

- **فیلترهای دائمی (شماره مسدود)**: هم فیلد رسمی تماس و هم شماره‌های نوشته‌شده
  مستقیم در متن آگهی چک می‌شوند (`data/filters/PhoneFilter.kt`)
- **کلمات ممنوعه**: اگر «مشاور» یا «املاک» در توضیحات باشد، آگهی همیشه مخفی
  می‌شود — بدون استثنا (`data/filters/ForbiddenKeywords.kt`)
- **تشخیص مالک با AI**: یک نسخه heuristic آفلاین (پیش‌فرض) + یک نسخه که مستقیم
  از گوشی به Claude API وصل می‌شود اگر در تنظیمات کلید API خودتان را وارد کنید
  (`data/filters/OwnerDetector.kt`)

## راه‌اندازی

1. Android Studio را باز کنید ← Open ← این پوشه را انتخاب کنید
2. صبر کنید Gradle Sync تمام شود
3. گوشی را با USB وصل کنید (USB Debugging فعال باشد) و Run ▶️ بزنید

نیازی به تنظیم هیچ آدرس سرور یا فایل پیکربندی نیست — همه‌چیز از همان لحظه
اول کار می‌کند.

### فعال‌سازی تحلیل هوشمند متن با AI (اختیاری)

در تب «تنظیمات»، کلید API آنتروپیک (Anthropic) خودتان را وارد کنید. بدون این
کلید، تشخیص مالک با روش قانون‌محور آفلاین (heuristic) انجام می‌شود که همیشه
در دسترس است.

## اسکن خودکار در پس‌زمینه (بدون نیاز به اسکرول دستی)

از تب «تنظیمات» می‌توانید «اسکن خودکار در پس‌زمینه» را روشن کنید. با روشن
بودن این گزینه:

- یک سرویس (`service/BackgroundScanService.kt`) هر چند دقیقه یک‌بار (قابل
  تنظیم، ۲ تا ۳۰ دقیقه) خودش هر جستجوی فعال را در یک WebView نامرئی
  (`data/webview/HeadlessDivarScanner.kt`) باز می‌کند، خودش تا چندین بار
  اسکرول می‌کند (`JsExtractionScripts.AUTO_SCROLL_SCRIPT`) تا آگهی‌های بیشتری
  بارگذاری شوند، و نتیجه را از همان مسیر همیشگی فیلتر می‌کند.
- هیچ کاری از شما لازم نیست؛ حتی اگر اپ بسته باشد، تا وقتی گوشی روشن است و
  این گزینه فعال است، بررسی ادامه دارد (با توجه به محدودیت‌های استاندارد
  اندروید برای Doze/بهینه‌سازی باتری روی برخی گوشی‌ها).
- بعد از ری‌استارت گوشی هم به‌طور خودکار از سر گرفته می‌شود
  (`service/BootCompletedReceiver.kt`).
- طبق درخواست صریح، فقط برای آگهی‌هایی که از **همهٔ** فیلترها رد شده‌اند
  (یعنی صد‌درصد مالک تشخیص داده شده‌اند) نوتیفیکیشن ارسال می‌شود؛ آگهی‌های
  حذف‌شده توسط فیلتر کلمات ممنوعه یا شماره مسدود، هیچ‌وقت نوتیفیکیشن نمی‌گیرند.

## محدودیت‌های شفاف

- شماره تماس و توضیحات کامل آگهی معمولاً فقط در **صفحه خود آگهی** نمایش داده
  می‌شوند، نه در لیست نتایج — به همین دلیل `ListingDetailFetcher.kt` برای هر
  آگهی جدید صفحه‌اش را هم می‌خواند تا فیلتر کلمات ممنوعه/شماره روی متن واقعی
  اجرا شود، نه فقط پیش‌نمایش کارت.
- سلکتورهای استخراج در `JsExtractionScripts.kt` بر پایه ساختار عمومی HTML
  حدس زده شده‌اند (بدون دسترسی مستقیم به صفحه واقعی دیوار در این محیط توسعه)
  و ممکن است بعد از تغییرات آینده‌ی سایت دیوار نیاز به تنظیم جزئی داشته باشند.
- «فیلتر صد‌درصد» یعنی فیلتر کلمات ممنوعه (مشاور/املاک) قطعی و بدون استثناست؛
  ولی تشخیص مالک/مشاور برای آگهی‌هایی که این دو کلمه را ندارند همچنان یک
  حدس آماری (heuristic یا مدل زبانی) است و مثل هر سیستم تشخیص دیگری صد‌درصد
  خطای صفر تضمین‌شده ندارد — اگر آگهی نادرستی دیدید، آستانه را در تنظیمات
  بالاتر ببرید یا کلید API را برای تحلیل دقیق‌تر وارد کنید.

## تست‌ها

تست‌های واحد برای منطق فیلترها در `app/src/test/java/.../data/filters/` قرار

## گرفتن APK از طریق GitHub (بدون Android Studio)

پوشه‌ی `.github/workflows/build-apk.yml` یک GitHub Action است که با هر
push به شاخه‌ی `main` (یا دستی از تب Actions) خودش پروژه را کامپایل کرده
و یک APK دیباگ می‌سازد:

1. پروژه را در گیت‌هاب push کنید.
2. تب **Actions** ریپو را باز کنید → روی آخرین اجرای «Build debug APK» بزنید.
3. پایین همان صفحه، بخش **Artifacts** یک فایل zip به‌نام
   `DivarSmartSearch-debug-apk` دارد — دانلودش کنید، داخلش
   `app-debug.apk` است.
4. آن APK را روی گوشی کپی کنید و نصب کنید (باید «نصب از منابع نامعتبر»
   را برای همان اپ دانلودکننده فعال کنید).

نکته‌ها:
- این APK **دیباگ** است (با کلید امضای پیش‌فرض دیباگ اندروید) — برای
  استفاده‌ی شخصی خودتان کاملاً کافی است، فقط برای انتشار در Play Store
  مناسب نیست.
- هرگز کلید امضای release (فایل `.jks`/`.keystore`) را داخل ریپو کامیت
  نکنید — `.gitignore` همین الان جلوی این را می‌گیرد.

## گذاشتن روی گیت‌هاب و گرفتن فایل APK (بدون نیاز به کامپیوتر برای بیلد)

این پروژه یک Workflow آماده در مسیر `.github/workflows/build-apk.yml` دارد که با
گیت‌هاب اکشن (GitHub Actions) به‌صورت خودکار پروژه را کامپایل می‌کند و فایل
APK را می‌سازد — یعنی خودتان لازم نیست Android Studio یا Gradle را نصب کنید.

### مرحله ۱ — ساخت ریپازیتوری و پوش کردن کد

```bash
cd DivarSmartSearch          # پوشه‌ای که این فایل‌ها داخلش است
git init
git add .
git commit -m "Initial commit: Divar Smart Search Android app"
git branch -M main
git remote add origin https://github.com/<username>/<repo-name>.git
git push -u origin main
```

(به جای `<username>` و `<repo-name>` نام کاربری و اسم ریپازیتوری خودتان را که
از قبل در گیت‌هاب ساخته‌اید بگذارید.)

### مرحله ۲ — دانلود فایل APK بعد از بیلد خودکار

1. وارد صفحه ریپازیتوری در گیت‌هاب شوید
2. روی تب **Actions** بزنید
3. اجرای (run) با عنوان **Build APK** را باز کنید (به‌محض پوش شدن کد خودش شروع می‌شود)
4. چند دقیقه صبر کنید تا سبز شود ✅
5. پایین همان صفحه، بخش **Artifacts** یک فایل به اسم
   `DivarSmartSearch-debug-apk` می‌بینید — آن را دانلود و از حالت zip خارج
   کنید تا فایل `.apk` را داشته باشید

این APK نسخه‌ی **debug** است؛ روی گوشی خودتان قابل نصب است (باید نصب از منابع
ناشناس/Unknown sources را برای آن فعال کنید) اما برای انتشار عمومی مناسب
نیست.

### مرحله ۳ (اختیاری) — گرفتن نسخه Release با یک تگ

اگر یک نسخه رسمی‌تر (بهینه‌شده و minify‌شده) می‌خواهید:

```bash
git tag v1.0.0
git push origin v1.0.0
```

با پوش شدن تگ، Workflow دوم (`release-apk.yml`) اجرا می‌شود و یک
**GitHub Release** با فایل APK پیوست‌شده می‌سازد (قابل دیدن در تب
**Releases** ریپازیتوری).

⚠️ به‌صورت پیش‌فرض این APK **امضا نشده** (unsigned) است. برای اینکه مستقیم
روی گوشی نصب شود باید امضایش کنید، یا این ۴ Secret را در تنظیمات ریپازیتوری
اضافه کنید تا Workflow خودش امضا کند:

`Settings → Secrets and variables → Actions → New repository secret`

| نام Secret | مقدار |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | فایل keystore شما، انکودشده با `base64 -w0 your.keystore` |
| `RELEASE_KEYSTORE_PASSWORD` | پسورد keystore |
| `RELEASE_KEY_ALIAS` | نام alias کلید |
| `RELEASE_KEY_PASSWORD` | پسورد کلید |

اگر keystore ندارید، می‌توانید یکی با دستور زیر بسازید (روی کامپیوتر خودتان،
با نصب بودن JDK):

```bash
keytool -genkeypair -v -keystore release.keystore -alias divar_key \
  -keyalg RSA -keysize 2048 -validity 10000
```

### توسعه محلی (اختیاری)

اگر می‌خواهید روی کامپیوتر خودتان هم پروژه را باز کنید، Android Studio را نصب
کنید و پوشه پروژه را با «Open» انتخاب کنید — Android Studio به‌صورت خودکار
فایل‌های Gradle Wrapper را می‌سازد (چون این‌ها در ریپازیتوری قرار داده
نشده‌اند تا حجم آن کم بماند).
